# Памятка владельца — как работать с ИИ-командой

> Краткая версия для агентов: `.cursor/rules/owner-interaction.mdc`  
> Обновлено: 2026-07-27 (после аудита команды)

## Главное правило

**Все ваши сообщения в чате — для Jarvis.** `@jarvis` можно писать для ясности, но **не обязательно**: команда по умолчанию считает любое ваше сообщение обращением к координатору.

Jarvis ведёт сессию, делегирует специалистам и помнит контекст **в рамках этого чата**.

---

## Как вы работаете (сессия в одном чате)

### Старт задачи

Достаточно описать цель — с `@jarvis` или без:

```
@jarvis Делаем виджет умного поиска
Делаем виджет умного поиска
```

Оба варианта равнозначны.

### Продолжение — просто пишете

```
Чекбокс «скрыть цену» не работает
Добавь поиск по артикулу
После тестов поправь отступы на мобилке
```

**Не нужно** повторять `@jarvis` — контекст чата + неявное обращение к Jarvis.

### Когда явно обозначить новую тему

| Ситуация | Как |
|----------|-----|
| Другой продукт / SEO / стратегия | «Новая тема: …» или новый чат |
| Новый ПК | новый чат + `@knowledge/…` |
| Стоп / pivot | «Стоп, меняем: …» |
| Доработки текущего виджета | просто текст |

## Что говорить — хорошие запросы

### Операционные задачи

```
@jarvis Сделай виджет inSales для … — полный цикл
@jarvis SEO-аудит страницы https://danforge.ru/…
@jarvis Обнови Kwork-описание для quick search
@jarvis Зафиксируй owner edit: armedf, переименовал вкладки в админке
```

**Формула:** что нужно + зачем + срок (если важен) + ссылки/скрины.

### Стратегия (без немедленного кода)

```
@jarvis Давай обсудим новые продукты для inSales
@jarvis Ретроспектива за последние 2 месяца
@jarvis Составь план работ на квартал
```

Jarvis **не запустит Programmer** — только анализ, roadmap, ideas-backlog.

### Решения и эскалации

```
@jarvis Утверждаю план из artifacts/…/04-plan.md
@jarvis Пропустить gate: spec-review — срочный hotfix
@jarvis Стоп, меняем направление: …
```

### Полезные вложения

- HTML-фрагмент с `data-*` с живого магазина (диагностика виджета)
- Скрин бага в редакторе inSales
- `@artifacts/…` или `@knowledge/…` для контекста с другого ПК

## Чего не говорить (или говорить иначе)

| ❌ Плохо | ✅ Лучше |
|----------|----------|
| «Срочно, без плана, просто почини» (виджет >1 ч) | «Hotfix: {симптом}, магазин X» — Jarvis решит маршрут; для skip gate: **«пропустить gate: …»** |
| «Сделай лучше» | «Увеличить конверсию CTA на странице модуля X» |
| Править виджет в админке молча | **«Owner edit: …»** (можно без @jarvis, если чат уже про этот виджет) |
| «Programmer, сделай …» (вызывать роль вручную) | Просто опишите задачу — Jarvis делегирует сам |
| Два противоречащих ТЗ в одном сообщении | Одно направление; смена — явное **«стоп, новое ТЗ»** |
| «Опубликуй на прод» без проверки | «Готово к публикации после live-check» — SEO/Tilda вручную |

---

## Когда можно обойти процесс

Только **явной фразой**:

```
пропустить gate: {spec-review | plan-review | code-review}
hotfix без ретро
```

Jarvis запишет в `artifacts/{task-id}/00-owner-decisions.md`.  
Без этой фразы gates **обязательны** — это защита от повторения багов reviews 10.07.

## Ваши обязанности (что команда не сделает за вас)

| Зона | Кто |
|------|-----|
| Правки в **Tilda** (danforge.ru) | Вы вручную по инструкциям SEO/Designer |
| **Публикация** Kwork, цены, оплата | Вы |
| **Доступы** inSales, GitHub, хостинг | Вы (не класть секреты в чат) |
| **Пилот на клиентском магазине** — установка виджета | Вы или по runbook Programmer |
| **Git push** с Desktop/ноутбука | Вы (команда коммитит только по запросу) |
| **Бизнес-решения**: цены, ниша, отказ от фичи | Вы |

## Типовые сценарии

### Новый виджет inSales

1. `@jarvis Новый виджет: {описание}` (или «полный цикл»)
2. В **этом чате** — ответы на вопросы, правки после тестов **без @jarvis**
3. Утвердить план, когда Jarvis принесёт (можно: «план ок, делай»)
4. Smoke в магазине по чеклисту
5. Публикация danforge + Kwork — вы

**Ожидаемый срок:** 3–10 дней в зависимости от сложности.

### Баг на живом магазине

1. Скрин + URL + что ожидали
2. В активном чате про виджет — просто описать баг; **новый чат** — `@jarvis Баг виджета X на {магазин}`
3. Если правили в админке — **owner edit** (см. выше)
4. После 2-й итерации фикса Jarvis может остановить и предложить ретро — **это нормально**

### Страница danforge / статья

1. `@jarvis SEO + тексты для страницы …`
2. Получить markdown/Tilda-инструкции
3. Внести в Tilda сами
4. `@jarvis Live-check страницы …` — сверка с эталоном

### Смена устройства

1. `git pull` на новом ПК
2. Новый чат + `@knowledge/strategy/roadmap.md` или нужный артефакт
3. История старых чатов **не переносится** — контекст в файлах

## Словарь команд

| Фраза | Эффект |
|-------|--------|
| **полный цикл** | Analyst → … → Code Reviewer → чеклист |
| **упрощённый** | Analyst → Planner → Programmer → Code Reviewer |
| **только анализ** | Analyst, без кода |
| **live-check** | SEO + skill tilda-live-check |
| **owner edit** | Протокол фиксации ваших правок в админке |
| **ретро** | Ретроспектива, обновление roadmap/KB |

---

## Чего ждать от команды

- Артефакты в `artifacts/YYYY-MM-DD-название/`
- Вердикты **APPROVED** / **NEEDS_REVISION** на этапах review
- Подпись роли в ответах: **Jarvis:**, **Analyst:** …
- Эскалация, если блокер или стратегический выбор

## Чего не ждать

- Мгновенный код без плана на крупные виджеты
- Прямое редактирование Tilda
- Память прошлых чатов на другом ПК
- Деплой без вашего участия (доступы)
