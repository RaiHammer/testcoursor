# UX: категории + статьи + товары — df_quick_search v0.0.12

**Контекст:** armedf.ru (мода/милитари), запрос «Футболка» → 1 категория, 58 статей, 50 товаров.  
**Текущий порядок:** Категории → Статьи (8 заголовков) → Товары (сетка).  
**Цель:** товары — primary; категории — быстрый переход; статьи — secondary, не блокируют покупку.

---

## Вариант A — «Товары первыми + компактные статьи» (single scroll)

### Wireframe

**Mobile & Desktop (одинаковая логика, различается только cols сетки):**

```
┌─────────────────────────────────────┐
│ [×]                          ПОИСК  │
│ Футболка________________________    │  ← input
├─────────────────────────────────────┤
│ КАТЕГОРИИ                           │
│ [ ФУТБОЛКИ ]                        │  ← chips, 1 строка
├─────────────────────────────────────┤
│ ТОВАРЫ (50)                         │
│ ┌────┐ ┌────┐                       │
│ │img │ │img │  … сетка 2/3/4 col    │  ← primary, сразу после категорий
│ └────┘ └────┘                       │
│ [ Показать ещё ]                    │
├─────────────────────────────────────┤
│ ▼ СТАТЬИ (58)          [развернуть] │  ← accordion, collapsed по умолчанию
│   (свёрнуто: 0–1 строка высоты)     │
└─────────────────────────────────────┘

Развёрнутый accordion:
│ ▲ СТАТЬИ (58)                       │
│ • Как выбрать футболку…             │  max 5 строк + «Все статьи → /search?q=»
│ • Обзор камуфляжа…                  │
```

**Desktop дополнение:** sticky chips под input при скролле результатов.

### Паттерны

| Паттерн | Решение |
|---------|---------|
| Single scroll | Да — один `.df-quick-search__results` |
| Accordion | Только для статей, default collapsed |
| Tabs | Нет |
| Split columns | Нет |

### Плюсы (ecommerce)

- Товары видны без скролла при типичном запросе с 1 категорией.
- Категории остаются наверху — быстрый переход в «Футболки».
- Минимальный diff: перестановка секций + CSS accordion.
- SEO-статьи доступны, но не мешают конверсии.

### Минусы

- 58 статей в accordion — длинный список при раскрытии (нужен cap 5–8 + ссылка «Все»).
- На desktop sidebar мог бы показать статьи параллельно с товарами — здесь нет.

### Когда использовать

Базовый v0.0.12, если приоритет — скорость внедрения и фикс «статьи отталкивают товары».

## Вариант B — «Split: sidebar контент / main товары» (desktop) + tabs (mobile)

### Wireframe

**Desktop ≥768px:**

```
┌──────────────────────────────────────────────────────────┐
│ [×]  Футболка________________________           ПОИСК    │
├──────────────┬───────────────────────────────────────────┤
│ КАТЕГОРИИ    │ ТОВАРЫ (50)                              │
│ [ФУТБОЛКИ]   │ ┌────┐ ┌────┐ ┌────┐ ┌────┐              │
│              │ │    │ │    │ │    │ │    │  4 col grid  │
│ СТАТЬИ (58)  │ └────┘ └────┘ └────┘ └────┘              │
│ • заголовок  │ ┌────┐ ┌────┐ …                          │
│ • заголовок  │ [ Показать ещё ]                           │
│ • заголовок  │                                           │
│ … max 6      │                                           │
│ Все статьи → │                                           │
│              │                                           │
│ ~240–280px   │ flex 1, scroll независимый опционально   │
└──────────────┴───────────────────────────────────────────┘
```

**Mobile <768px:**

```
┌─────────────────────────────────────┐
│ [×]  Футболка____________    ПОИСК  │
│ [ ФУТБОЛКИ ]                        │  ← chips sticky
│ ┌─────────┬─────────┐               │
│ │ Товары  │ Статьи  │               │  ← 2 tabs, default Товары
│ │  (50)   │  (58)   │               │
│ └─────────┴─────────┘               │
│ … контент активной вкладки …        │
└─────────────────────────────────────┘
```

### Паттерны

| Паттерн | Mobile | Desktop |
|---------|--------|---------|
| Tabs | Товары / Статьи | Нет |
| Split columns | Нет | Sidebar + main |
| Accordion | Нет | Нет (статьи в sidebar) |
| Single scroll | Внутри tab | Два столбца, общий scroll панели |

### Плюсы

- Desktop: товары и статьи видны одновременно — хорошо для «обзор + покупка» (милитари-гайды).
- Mobile tabs убирают конкуренцию за вертикальное пространство.
- Категории всегда доступны (chips над tabs на mobile).

### Минусы

- Существенно больше CSS/JS (breakpoints, tab state, ARIA).
- Sidebar на узком tablet (768–900px) может сжимать сетку до 2 col.
- Два scroll-контейнера на desktop — риск путаницы на iOS.

### Когда использовать

v0.0.13+, если armedf.ru активно использует статьи как воронку (обзоры, size guides).

## Вариант C — «Segmented tabs + категории-rail» (все breakpoints)

### Wireframe

**Mobile & Desktop:**

```
┌─────────────────────────────────────┐
│ [×]  Футболка____________    ПОИСК  │
│ [ ФУТБОЛКИ ]  (+ другие chips)      │  ← rail, sticky
├─────────────────────────────────────┤
│ [ Товары (50) │ Статьи (58) │ Всё ] │  ← segmented control
├─────────────────────────────────────┤
│ … только контент выбранного …       │
│                                     │
│ Tab «Товары»: только сетка          │
│ Tab «Статьи»: список 8 + load more  │
│ Tab «Всё»: cat + 4 статьи + 12 товар│
└─────────────────────────────────────┘
```

Default tab: **Товары (50)**.

### Паттерны

| Паттерн | Решение |
|---------|---------|
| Tabs | 3 сегмента с счётчиками |
| Single scroll | Внутри активного tab |
| Accordion | Нет |
| Split columns | Нет |

### Плюсы

- Чёткое разделение intent: «хочу купить» vs «хочу почитать».
- Счётчики в табах снимают тревогу «58 статей — где товары?».
- Tab «Всё» — компромисс для curious users без блокировки default.

### Минусы

- Extra tap для статей (OK для secondary content).
- Три состояния рендера — больше QA.
- Tab «Всё» дублирует старый single-scroll — нужны лимиты (4 статьи + 12 товаров).

### Когда использовать

Если analytics покажет, что >30% пользователей кликают статьи из поиска.

## Сравнение паттернов (cheat sheet)

| Паттерн | Лучше когда | Хуже когда |
|---------|-------------|------------|
| **Single scroll** | Мало секций или чёткий порядок приоритета | Много secondary контента выше primary |
| **Accordion** | Secondary блок редко нужен, но должен быть рядом | >10 пунктов и частые раскрытия |
| **Tabs** | Равнозначные типы контента или mobile space tight | Нужно видеть всё сразу (desktop shopping) |
| **Split columns** | Wide screen, параллельный browse | Mobile, узкий tablet |

## Рекомендация для v0.0.12

**Внедрить Вариант A** (products-first + collapsed articles):

1. **Порядок секций:** Категории → Товары → Статьи (accordion collapsed).
2. **Статьи:** показывать max 5–8 при раскрытии; footer-link «Все результаты на сайте» → `/search?q=…` (если inSales отдаёт) или список блога.
3. **Категории:** без изменений; optional `position: sticky` под form на scroll.
4. **Настройка:** `articles_collapsed_default: true` в settings (для A/B).

**Почему не B/C сразу:** v0.0.10 только добавил статьи; armedf.ru — conversion-first; A закрывает главную боль одним reorder + ~40 строк JS/CSS. B — backlog v0.0.13 при подтверждённом спросе на статьи из поиска.

## Подсказки программисту (без кода)

**A11y:** `aria-expanded` на toggle accordion; tab-паттерн — только если пойдёте в B/C.
