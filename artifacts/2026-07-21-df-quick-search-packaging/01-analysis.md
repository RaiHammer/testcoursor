## 1. Продукт

**Быстрый поиск DanForge** — коммерческий виджет inSales: полноэкранная live-панель поиска с фото, ценами (включая старую), категориями, опционально статьями блога, поиском по SKU и честной выдачей без «мусорных» fallback. Не подменяет штатный AjaxSearch — открывает свою панель по CSS-триггерам шапки.

| Параметр | Значение |
|----------|----------|
| Handle | `danforge_quick_search` |
| Версия | **v0.0.24** |
| Платформа | inSales **gen-2** и **gen-4** |
| Пилот | armedf.ru |
| Лицензия | коммерческая, **один магазин — одна лицензия** |
| Статус | production-ready (по README) |

## 2. УТП (5–7 пунктов)

Относительно **штатного AjaxSearch** и **правки темы**:

1. **Полноэкранная сетка вместо dropdown** — крупные фото (5 форматов), цена + зачёркнутая старая цена, бейдж «Нет в наличии»; AjaxSearch даёт узкий autocomplete без категорий и статей.
2. **Гибрид suggestions + `/search.json`** — больше релевантных позиций, чем типичный потолок suggestions (~10–12), плюс enrich через `/products_by_id` (фото, категории, variants), которых suggestions не отдаёт.
3. **Поиск по SKU всех вариантов** + фильтр нулевой цены — явная ценность для B2B/опта; в теме это обычно «если сделают».
4. **Товары + категории + статьи в одной панели** (split desktop / tabs mobile) — AjaxSearch статей не ищет; правка темы тянет отдельный кастомный JS/Liquid.
5. **Без правки темы** — виджет отдельно, 19 настроек в админке, триггеры через CSS-селекторы с capture-фазой (не конфликтует с JS темы).
6. **Честная выдача и UX пустоты** — строгий фильтр без нерелевантного fallback; zero-results с ссылкой на `/search` и подсказками категорий; «N из M» + incremental load more.
7. **A11y + GTM из коробки** — dialog/focus trap/aria-live/keyboard tabs; события `df_qs_search`, `df_qs_product_click`, `df_qs_zero_results`, `df_qs_category_click` — у AjaxSearch и типичной правки темы этого обычно нет.

## 3. Сегменты ЦА

### 3.1 E-commerce (каталог)

| | |
|--|--|
| **Кто** | Магазины с ассортиментом, где поиск — основной shortcut в карточку |
| **Боли** | Dropdown без фото/цен; покупатель не видит наличие и скидку; уходит на `/search` и теряет скорость; тема «ломается» при каждом обновлении, если поиск вшит в шапку |
| **Messaging** | «Покупатель видит товар как в каталоге: фото, цена, скидка, наличие — за 2 символа, без ухода со страницы.» |

### 3.2 Content + commerce (блог + товары, как armedf.ru)

| | |
|--|--|
| **Кто** | Магазины с обзорами, инструкциями, гайдами «как выбрать» |
| **Боли** | Поиск находит только SKU/название; статьи «как выбрать» живут отдельно; большой блог (500+) не укладывается в один индекс |
| **Messaging** | «Один поиск — товар и статья. В панели сразу каталог и контент; если статей больше индекса — честная кнопка «Все статьи →».» |
| **Факт для оффера** | Пилот armedf.ru; `show_articles` опционально (default OFF); индекс до **100 статей на блог** (Liquid) |

### 3.3 B2B / SKU-поиск

| | |
|--|--|
| **Кто** | Опт, дилеры, склады с заказами по артикулу |
| **Боли** | Клиент знает артикул, а штатный поиск его «не видит» или путает с названием; в выдаче мешают позиции «цена 0 / запросите» |
| **Messaging** | «Ищем по артикулу всех вариантов. Нулевые цены можно скрыть — в быстрой выдаче только то, что можно купить.» |

## 4. Конкуренты

### Факты из knowledge

- Таблица конкурентов по URL для поиска **не заполнена** (`knowledge/danforge/competitors.md` — шаблон + общие выводы по нише, без виджетов поиска).
- Публичных эталонов DanForge по «поиску» нет — ориентиры только **корзина** и **отзывы**.

### Типичные паттерны рынка (наблюдения / гипотезы — помечено)

| Паттерн | Что обычно продают | Ценовая вилка (ориентир, **мало данных**) |
|---------|-------------------|-------------------------------------------|
| Kwork: «доработать поиск в шапке» | Правка Liquid/JS темы под клиента | ~3 000–10 000 ₽ разово *(гипотеза по типичным кворкам inSales-правок)* |
| Kwork / фриланс: «красивый autocomplete» | Dropdown с фото, без статей/категорий | ~2 000–6 000 ₽ *(гипотеза)* |
| Кастом «как у крупных» | Полноэкран / отдельный модуль | Редко как готовый продукт; чаще проект 15 000+ ₽ |
| Штатный AjaxSearch | Бесплатно в теме | Нулевая цена, слабый UX |

**Где мало данных (честно):** нет свежего среза Kwork/маркетплейса inSales именно по «виджету быстрого поиска»; нельзя назвать конкретных конкурентов и их цены без аудита. Сильная сторона оффера DanForge — **готовый продукт + пилот + документация**, а не «напишем с нуля».

**Вывод для позиционирования:** конкурируем не с «ещё одним dropdown», а с **правкой темы** (дорого поддерживать) и с **AjaxSearch** (бесплатно, но слабо конвертирует). Цена должна быть выше корзины-файлов и ближе к «установке UX-модуля», ниже/на уровне отзывов без ежемесячного сопровождения.

## 6. Состав коммерческого пакета

### Входит в лицензию (A)

- Файлы виджета (`widget/`: manifest gen-2/gen-4, liquid/js/scss, settings)
- Право использования на **одном** магазине inSales
- Документация установки/настроек (README / FEATURES)
- Обновления минорных багфиксов по политике DanForge *(детали политики — уточнить у владельца)*

### Входит в установку (B = A + работы)

- Выбор/подготовка манифеста gen-2 или gen-4
- Загрузка в админку, размещение (header/outside — gen 4)
- Настройка `trigger_selectors` под тему
- Включение базовой выдачи: фото, цены, категории, лимит, колонки (по согласованию)
- Смоук: открытие/закрытие, кириллица, 1–2 тестовых запроса, переход на `/search`
- Краткая инструкция «как выключить / поменять placeholder»

### Входит в пакет C (B + поиск по статьям + донастройка)

**«Статьи» в названии пакета C = настройка функции поиска по статьям блога в виджете, а не контент-услуги.**

- Всё из B
- Включение и конфигурация: `show_articles` ON, `article_blog_handles`, `articles_blog_url`, `articles_display_limit`, lazy load + server reload
- Настройка сетки/формата фото под витрину
- При необходимости: `hide_zero_price`, бейдж наличия — под сценарий B2B/розница
- Приёмка сценариев: товары + статьи в панели + zero-results + «Все статьи →» (если индекс неполный)
- Опционально: подсказка по dataLayer-событиям для GTM клиента *(настройка тегов GTM клиента — обычно отдельно)*

### НЕ входит (границы — фиксировать в оффере)

- **Написание / редактура статей блога для клиента** (пакет C только подключает уже существующий блог к поиску)
- Правка/редизайн всей шапки или темы
- Серверная пагинация товаров сверх загруженного списка; снятие лимита **100 статей/блог** платформы
- Гарантия «найдёт всё как Google» / полнотекстовый поиск по телу статьи (в FEATURES: title, tags, related products)
- Интеграция сторонних поисковых движков (Elastic и т.п.)
- Ежемесячное сопровождение (в отличие от отзывов с Яндексом)
- Установка на второй магазин без новой лицензии
- Настройка рекламных/аналитических кабинетов клиента «под ключ» (кроме передачи имён событий)

## 7. Риски и ограничения — как говорить клиенту

Источник: таблица «Известные ограничения» в FEATURES.md.

| Ограничение | Честная формулировка для клиента |
|-------------|----------------------------------|
| **≤100 статей на блог** в клиентском индексе (Liquid paginate) | «В панели индексируем до 100 статей на каждый указанный блог. Если статей больше — в выдаче будет срез + кнопка „Все статьи →“ на страницу блога. Для armedf-сценария с 500+ это нормальный и честный UX.» |
| **Нет публичного API статей** | «Статьи только из Liquid-индекса темы, не из внешнего API. Включение статей требует сохранения с пересборкой (server reload).» |
| **«Показать ещё» — client-side** | «Кнопка раскрывает уже загруженный список порциями („N из M“), это не бесконечная подгрузка с сервера. Полный каталог по запросу — через „Все результаты“ / Enter на страницу `/search`.» |
| **Suggestions ~10–12** | «Быстрый слой платформы отдаёт около десятка подсказок; виджет дополняет выдачу через `/search.json` и обогащает карточки. Это сильнее чистого AjaxSearch, но не замена полноценной странице поиска.» |
| **Gen-2 vs gen-4** | «Поддерживаем оба поколения; для gen-2 свой манифест (без header/outside в widget_list_kinds).» |

**Тон:** не скрывать лимиты в FAQ/договоре; продавать **контроль и честность выдачи**, а не «безлимитный Elasticsearch».

| Шаг | Канал | Действие |

| **3** | **`/services/modules`** | Карточка в каталоге модулей + перелинковка с product page |

**Порядок запуска (рекомендация):**

1. Скрины desktop/mobile (пилот armedf.ru или demo-магазин) + 15–30 сек видео открытия панели  
2. Тексты страницы (SEO/Designer) по messaging pillars ниже  
3. Публикация **страницы на danforge.ru** (владелец / Tilda)  
4. Карточка в **`/services/modules`**

Публикация в Tilda/Kwork — зона владельца; команда готовит материалы.

## 9. Messaging pillars (tone of voice)

Прямой тон, выгода владельцу магазина, без воды. Единый словарь для SEO / Designer / копирайта:

1. **«Поиск как витрина, не как строка.»**  
   Полноэкранная панель: фото, цена, скидка, наличие — покупатель решает быстрее.

2. **«Товар и статья в одном запросе.»**  
   Для магазинов с блогом: нашёл и SKU, и «как выбрать» — без второго инструмента.

3. **«Артикул находит с первого раза.»**  
   Поиск по SKU всех вариантов + опция скрыть нулевые цены — для опта и склада.

4. **«Без правки темы и без сюрпризов в выдаче.»**  
   Виджет в админке; строгая фильтрация — пусто, если нет совпадений, а не чужой ассортимент.

5. **«Честные лимиты — честный результат.»**  
   До 100 статей в индексе на блог, «N из M», ссылка на полный `/search` — без обещаний «найдём всё на свете».

**Не использовать в маркетинге:** обещания снятия Liquid-лимита 100; «замена Google/Elastic»; гарантия идеального поиска по полному тексту статей (этого нет в FEATURES).
