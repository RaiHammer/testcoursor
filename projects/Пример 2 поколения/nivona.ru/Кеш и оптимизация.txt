# Тег prefetch

Тег prefetch задаёт, сколько элементов подгружать в цикле и в каком порядке их показывать. Его нужно оборачивать вокруг блока, где вы выводите коллекцию (товары или отзывы). Так вы ограничиваете выборку и управляете сортировкой без лишней нагрузки на страницу.

---

## Товары (коллекция)

Оборачивайте тег вокруг цикла по товарам коллекции. Обязательно укажите коллекцию и лимит.

Базовый пример:

{% prefetch collection.products limit 12 %}
  {% for product in collection.products %}
    {{ product.title }}
  {% endfor %}
{% endprefetch %}

- collection.products — подставьте свою переменную коллекции (например, collection.products, collections[0].products).
- limit — число товаров (от 1 до 100). Можно указать число или свою переменную.

Дополнительные параметры (через запятую после limit):

- sort — ключ сортировки (см. раздел «Сортировка товаров»).
- offset — с какой позиции начинать выборку (для постраничной выдачи).
- only_available — true — только товары в наличии, false — все (в т.ч. отсутствующие).

Пример с сортировкой и только доступными товарами:

{% prefetch collection.products limit 24, sort: 'price', only_available: true %}
  {% for product in collection.products %}
    {{ product.title }} — {{ product.price }}
  {% endfor %}
{% endprefetch %}

Внутри блока prefetch у коллекции доступно свойство prefetch_count — количество реально подгруженных элементов в рамках текущего лимита.

---

## Отзывы (account.reviews)

Тег работает с отзывами магазина: account.reviews, account.reviews_not_spam, account.reviews_spam.

Базовый пример (опубликованные отзывы без спама):

{% prefetch account.reviews_not_spam limit 10 %}
  {% for review in account.reviews_not_spam %}
    {{ review.content }} — {{ review.rating }}
  {% endfor %}
{% endprefetch %}

Параметры те же: limit (1–100), при необходимости sort и offset.

Пример с сортировкой по дате (новые первые):

{% prefetch account.reviews_not_spam limit 5, sort: 'date_desc' %}
  {% for review in account.reviews_not_spam %}
    {{ review.content }}
  {% endfor %}
{% endprefetch %}

Внутри блока у коллекции отзывов тоже доступно prefetch_count.

## Сортировка

### Товары

Укажите параметр sort с одним из ключей:

| Ключ | Описание |
|------|----------|
| title | По названию (А–Я) |
| descending_title | По названию (Я–А) |
| price | По цене (сначала дешевле) |
| descending_price | По цене (сначала дороже) |
| old_price | По старой цене (сначала дешевле) |
| descending_old_price | По старой цене (сначала дороже) |
| price_available | По цене среди товаров в наличии |
| descending_price_available | По цене среди товаров в наличии (дороже сначала) |
| discount | По размеру скидки (сначала меньше) |
| descending_discount | По размеру скидки (сначала больше) |
| discount_available | По скидке среди товаров в наличии |
| descending_discount_available | По скидке среди товаров в наличии (больше сначала) |
| age | По давности добавления (старые первые) |
| descending_age | По давности добавления (новые первые) |
| sort_weight | По весу сортировки (возрастание) |
| descending_sort_weight | По весу сортировки (убывание) |
| updated_at | По дате обновления (старые первые) |
| descending_updated_at | По дате обновления (новые первые) |
| popularity | По популярности |
| descending_popularity | По популярности (сначала популярнее) |
| relevance | По релевантности (при поиске) |
| manual | Вручную (порядок в коллекции) |

Пример: sort: 'descending_price' — сначала дорогие товары.

### Отзывы

Укажите sort с одним из ключей:

| Ключ | Описание |
|------|----------|
| date | По дате (старые первые) |
| date_desc | По дате (новые первые) |
| rating | По оценке (низкие первые) |
| rating_desc | По оценке (высокие первые) |
| rating_desc_date_desc | Сначала по оценке (высокие), затем по дате (новые) |
| rating_date_desc | Сначала по оценке (низкие), затем по дате (новые) |

Пример: sort: 'rating_desc_date_desc' — сначала отзывы с высокой оценкой, при равной оценке — более новые.

## Что в каждой коллекции

Всегда есть:

- id — число  
- parent_id — число или null  
- url — ссылка на коллекцию на сайте  
- title — название  
- has_subcollections — есть ли вложенные категории в каталоге  

По желанию (если добавить параметры в URL):

- menu_image — объект с картинкой или null  
- description — текст описания  
- products_count — сколько товаров в коллекции (число)  
- fields — объект: ключ = permalink доп. поля из настроек магазина, значение = то, что сохранено (может быть пусто / null)  

Если пришёл `menu_image` и он не null, там обычно есть ссылки на файлы: original_url, medium_url, small_url, thumb_url, плюс служебные id, created_at, image_processing.  

Если дополнительно задать правила размеров (image_resizing_rules с корректным size), может появиться `resized_urls`: это не список, а объект вида "480": "https://…", "240": "https://…". Без валидного size этого поля не будет — ошибки не будет.

## Метод 1. Несколько коллекций по id

Зачем: забрать карточки категорий, если уже знаете их id (например, из шаблона).

Адрес: GET /front_api/collections.json

Параметры:

- `ids` — обязательно по смыслу: id через запятую, например 5,12,88. За один раз не больше 100 id.  
- `menu_image=true` — добавить поле menu_image.  
- `description=true` — описание.  
- `products_count=true` — счётчик товаров.  
- `fields=permalink1,permalink2` — доп. поля по их permalink.  
- `image_resizing_rules` — опционально, вместе с картинкой: задаёт resized_urls (нужен валидный size; можно несколько правил для разных размеров).

Ответ: один массив collections. Категории, id которых не нашлись, просто не попадут в массив.

---

## Метод 2. Дети одной категории

Зачем: показать подкатегории внутри выбранной родительской (плоский список, без дерева).

Адрес: GET /front_api/collections/subcollections.json

Параметры:

- `id` — id родителя. Специальное значение `-1` значит: «дети у корневого уровня витрины» (первый уровень категорий под системным корнем дерева).  
- Остальное как в методе 1: menu_image, description, products_count, fields, image_resizing_rules.

Ответ: массив collections. Если детей нет — пустой массив [].

---

## Метод 3. Фрагмент дерева для меню

Зачем: одним запросом получить вложенное меню между уровнями каталога (например, 1-й и 2-й уровни).

Адрес: GET /front_api/collections/menu.json

Параметры:

- `start_level` — с какого уровня начинать отдавать узлы (по умолчанию 1).  
- `end_level` — до какого уровня строить дерево (по умолчанию 2).  
- `menu_image_for_level` — на каких уровнях отдавать картинку: например 1 или 1,2. Если не указать — картинка только на уровне start_level.  
- `description`, `products_count`, `fields`, `image_resizing_rules` — как выше; ресайз имеет смысл только там, где реально отдаётся menu_image.

Важно: здесь картинки включаются через `menu_image_for_level`, а не через menu_image=true (как в методах 1 и 2).
